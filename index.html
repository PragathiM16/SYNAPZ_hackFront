Capabilities

What CodeWhy actually does

Only implemented features listed here.

🔍

Behavior analysis

Describes what the code demonstrably does: control flow, inputs, outputs, and observable side effects. No claims about execution.

💡

Intent inference (clearly labelled)

Suggests plausible reasons for design choices. Every inference is explicitly marked so you know what is observation and what is interpretation.

📎

Code evidence

Cites the specific lines, variable names, and expressions from your actual code that support each claim. No invented references.

⚠️

Uncertainty disclosure

Identifies what cannot be concluded from the code alone: missing context, ambiguous logic, and limits of static analysis.

✅

Verification steps

Suggests concrete tests, input/output examples, and inspection steps you can run to confirm key claims before making changes.

🌐

Indian language support

Explanations in English, Hindi, Kannada, Tamil, Telugu, Bengali, Marathi, Gujarati, Malayalam, Punjabi, and Odia via Sarvam-105B.

What an explanation looks like

A static illustration. Run the explorer above for a live Sarvam-105B result.

Sample code

def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1  # not found
Behavior

Searches a sorted array for target using divide-and-conquer. Returns the index of the matching element, or -1 if not present. Runs in O(log n) time.

Possible intent (inference)

The // 2 integer division avoids float arithmetic. Using -1 as a sentinel rather than raising an exception suggests the caller checks the return value without a try/except wrapper.

Verification suggestion

Test with an empty array, a single-element array, and a target equal to the first and last elements to confirm edge-case behavior before relying on the -1 sentinel.
